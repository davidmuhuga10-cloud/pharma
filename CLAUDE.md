# Pharma — working rules

Read this before changing anything. These rules came from Kodi and apply here from now on.

1. **No gray text anywhere.** Text uses only the palette's text colours: `--ink` / `--ink-soft` (`#201E1B`), white on green, and the green, amber and red inks. Hierarchy comes from size, weight and letter-spacing, not from lighter text. Backgrounds and borders may stay neutral. `tests/banned-colours.test.js` enforces this.
2. **Every change updates the status documents** in the same commit: `README.md`, `PHARMA_PROJECT_STATUS.md` and `CHANGELOG.md`. A change with no entry is not finished.
3. **Test before anything lands.** Run the tests, check the affected pages at desktop (860px and wider) and phone widths (320-430px), and confirm nothing else broke. If something fails, fix it before moving on. Never stack changes on a broken build.
4. **No AI or assistant attribution** in commit messages, PR descriptions, code comments or docs. No "Co-Authored-By" trailers, no "generated by" lines.
5. **Buttons that send a request go through `act(btn, fn)`** so they show "Please wait..." and cannot be double-tapped.
6. **A new rule gets a test.** Add the test, then break the rule once on purpose to prove the test goes red, then fix it.
7. **Bump `CACHE_NAME` in `sw.js`** whenever `index.html`, `style.css`, `app.js` or another cached file changes.
8. **Don't change what wasn't asked.** If a root cause is unclear, ask.

## Commands

```bash
node tests/banned-colours.test.js     # no-gray-text rule
cd tests && npm install && node run_tests.js   # SQL tests; needs a local throwaway Postgres (see tests/README.md)
node --check app.js                    # syntax check
```
