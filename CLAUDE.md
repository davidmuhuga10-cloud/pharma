# Pharma — working rules

Read this before changing anything. These rules came from Kodi and apply here from now on.

1. **No gray text anywhere.** Text uses only the palette's text colours: `--ink` / `--ink-soft` (`#201E1B`), white on green, and the green, amber and red inks. Hierarchy comes from size, weight and letter-spacing, not from lighter text. Backgrounds and borders may stay neutral. `tests/banned-colours.test.js` enforces this.
2. **Every change updates the status documents** in the same commit: `README.md`, `PHARMA_PROJECT_STATUS.md` and `CHANGELOG.md`. A change with no entry is not finished.
3. **Test before anything lands.** Run the tests, check the affected pages at desktop (860px and wider) and phone widths (320-430px), and confirm nothing else broke. If something fails, fix it before moving on. Never stack changes on a broken build.
4. **No AI or assistant attribution** in commit messages, PR descriptions, code comments or docs. No "Co-Authored-By" trailers, no "generated by" lines.
5. **Buttons that send a request go through `act(btn, fn)`** so they show "Please wait..." and cannot be double-tapped.
6. **A new rule gets a test.** Add the test, then break the rule once on purpose to prove the test goes red, then fix it.
7. **Bump `CACHE_NAME` in `sw.js`** whenever `index.html`, `style.css`, anything in `js/` or another cached file changes.
8. **Android releases:** raise `versionCode` in `android/app/build.gradle` by 1 for every upload to Google Play, and back up the signing key in two places. `tests/android-shell.test.js` keeps the app's package name consistent.
9. **Don't change what wasn't asked.** If a root cause is unclear, ask.
10. **Code layout:** the app's code is in `js/`, one file per area (see `README.md`). New code goes in the file of the screen it belongs to. A new file must be added to `index.html` (before `main.js`, which stays last) and to `SHELL_FILES` in `sw.js`; `tests/js-split.test.js` fails if either is forgotten. Everything shares one global scope, so a function in one file can be called from another, but code that *runs* while the files load must only use things from files above it.
11. **Keep screens fast as data grows:** a screen must never download a whole history to add it up in the browser. Totals go in a database function (see `sales_report`, `supplier_balances`, `dashboard_data`); lists come a page at a time; never put a long list of ids in a request (`.in('id', [...])` fails past a few hundred). A new table that is filtered by pharmacy needs an index that starts with `pharmacy_id`.

## Commands

```bash
node tests/banned-colours.test.js     # no-gray-text rule
node tests/android-shell.test.js      # Android settings agree
node tests/native-shell.test.js       # print and back button inside the app
node tests/critical-css.test.js       # loading screen styles match everywhere
node tests/js-split.test.js           # js/ files in order, cached offline, init() once
node --experimental-strip-types tests/send-sms.test.js   # SMS sender logic
cd tests && npm install && node run_tests.js   # SQL tests; needs a local throwaway Postgres (see tests/README.md)
for f in js/*.js; do node --check $f; done   # syntax check
```
